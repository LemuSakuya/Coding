### 3. 原理说明

#### 3.1 串口通信原理
- UART 异步串行通信：起始位 + 8 数据位 + 停止位
- 波特率发生器：T1 工作在模式 2（8 位自动重装）
- 甲机使用中断方式接收（效率高，不阻塞主循环）
- 乙机使用查询方式发送（简单可靠）

#### 3.2 波特率公式
```
波特率 = (2^SMOD / 32) × (f_osc / (12 × (256 − TH1)))

当 SMOD = 0，f_osc = 11.0592MHz，目标 9600：
  TH1 = 256 − 11,059,200 / (12 × 32 × 9600)
      = 256 − 3 = 253 = 0xFD
```

#### 3.3 数码管驱动
- 共阴极数码管：公共端接地，段选高电平点亮
- 段码表：按 a(LSB)→b→c→d→e→f→g→dp(MSB) 排列
- 查表法：`P0 = seg_table[received_char]`

### 5. 软件设计

#### 5.1 甲机流程
```
初始化串口(9600bps, REN=1, ES=1, EA=1)
↓
默认显示 '0'
↓
等待串口中断
↓
RI=1 → 读 SBUF → 查表 → 驱动数码管 → 清除 RI
```

#### 5.2 乙机流程
```
初始化串口(9600bps, 仅发送)
↓
检测 P1.7 = 0 ?
  ├─ 否 → 继续检测
  └─ 是 → 消抖10ms
           ↓
           再次检测 P1.7 = 0 ?
             ├─ 否 → 继续检测（抖动）
             └─ 是 → 发送 g_send_index
                      ↓
                      g_send_index++
                      if > 4 → g_send_index = 0
                      ↓
                      等待按键释放
                      ↓
                      消抖10ms
```

### 7. 问题与思考

#### Q1：为什么选择 11.0592MHz 晶振？
11.0592MHz 可以整除波特率发生器的分频系数，产生精确的 9600、4800 等标准波特率，无累积误差。若使用 12MHz，TH1 计算值不是整数，会产生误码。

#### Q2：甲机为什么用中断接收而不用查询？
中断方式可以实时响应接收事件，不占用主循环时间。查询方式可能因主循环执行其他任务而错过数据帧。

#### Q3：如果按键消抖不充分会怎样？
一次机械按键可能产生多次电平跳变，导致发送多个字符，甲机数码管跳号。

#### Q4：两机不共地会怎样？
TXD/RXD 信号是电压信号，需要共同的参考地。不共地时接收端无法正确判断电平高低，通信失败。
